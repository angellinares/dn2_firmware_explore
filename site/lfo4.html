A Fourth LFO

The Digitone II has three LFOs per track and an empty fourth page under [MOD]. This fills it with a fourth LFO that behaves like the other three. Select your firmware file. Then download a signed image.

This tab does all the work in your browser. The page does not upload your firmware file, because the page has no server. The page is a set of static files on GitHub Pages. You can read all of its code in the repository.

Make sure that you can go back to stock before you flash a modified file. The Early Start-up Menu flashes the stock firmware over MIDI. Do this one time with the stock file, before you flash a modified file. Back up your +Drive. No tool here can recover it.

Apply LFO4 last. LFO4 copies the parameter table of the instrument to a new place with room for ten more records. From then on, the firmware reads the copy. A mod that edits that table must be in the image before LFO4 makes the copy. If not, the edit goes into a table that nothing reads.

Combines with FX Modulation, Modulation Destinations, the MIDI Arpeggiator and Arpeggiator p-locks (command line). Build those first. Then load their download here. LFO4 also combines with LFO Waves, which must also come first, and with the Boot Screen, in either order. All of them share one start-up loader and one appended area. This page adds LFO4 to the data that the area already holds.

2

What it adds

A fourth page under [MOD], with the controls of LFO1-3. Before it writes, the page checks that each address this mod changes holds its stock bytes. If an image is different anywhere, the page refuses it. It does not write the change in a place that only looks correct.

Where
On a synth track: [MOD], the fourth page. Its DEST browser works like LFO1-3's
Plays
Modulates on every voice, so polyphonic tracks and tracks that move between voices are modulated too
Keeps
Its settings are stored with the sound by SAVE PROJECT, and survive a power-cycle even without a save, like any stock parameter
Not included
MIDI: LFO4 has no NRPN numbers, so it cannot be set or recorded over MIDI
Writes
—

Confirmed on a Digitone II. The page opens with the stock LFO controls, and its DEST browser works. LFO4 modulates on every voice. An explicit SAVE PROJECT keeps its settings, and the settings stay after a power-cycle without a save. This page applies exactly the bytes of that build. A byte-for-byte check runs when we package the page.

None of Elektron's data ships with it. The copied parameter table has the 320 stock records and the ten records of LFO4, which are the LFO3 records with five fields changed. The page builds this table from your file when you push Build.

3

Build it

The image is rebuilt, re-signed with the key derived from your own file, and every integrity field is checked again. Nothing downloads unless all of them pass.

Combining with other mods

Each page applies one mod. To combine them, build on the other page first, then load its download here: this one goes last. It writes 204 places in section 3 and appends 23.7 KB to it.

  • FX Modulation: combines, applied first. LFO4 carries its ten Chorus record masks into the copy of the table. In the emulator, every LFO page, LFO4 included, lists the 24 FX destinations. Nobody has aimed LFO4 at one yet. The FX page refuses an image that this page built.
  • Modulation Destinations: combines, applied first. Its thirteen opened destinations are carried into the copy. That page refuses an image this page has built.
  • MIDI Arpeggiator: combines, in either order. No shared bytes.
  • Arpeggiator p-locks: combines, from the command line only: dnfw mods apply firmware.syx --mod arpplocks --mod lfo4.
  • Transient Swapper: combines. It only writes the DSP image.
  • LFO Waves: combines. Build LFO Waves first. Then load its download here. LFO Waves edits three records of the parameter table, and LFO4 copies that table. So the order matters, and the LFO Waves page refuses an image this page has built.
  • Boot Screen: combines, in either order. Both add to the one appended area.
  • Waverider: combines, in either order. The platform writes the bounds both mods widen: the parameter count for LFO4, the machine count for Waverider.

What "combines" means here. A check makes sure that the bytes of the two mods do not overlap. A test compares the output of this page with the output of the command line, byte for byte, alone and after FX Modulation. LFO4 passed on hardware alone. It also passed on 2026-09-30 in one combination: LFO Waves, Boot Screen and LFO4.
