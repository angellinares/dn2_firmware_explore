Digitone II Mods / fx modulation

FX Modulation

Point an LFO at the Chorus, the Delay or the Reverb. Twenty-four new entries in the DEST list, chosen by name. Select your firmware file. Then download a signed image.

Make sure that you can go back to stock before you flash a modified file. The Early Start-up Menu flashes the stock firmware over MIDI. Do this one time with the stock file, before you flash a modified file. Back up your +Drive. No tool here can recover it.

What opens

All twenty-four, or none. Before it writes, the page checks that each address this mod changes holds its stock bytes. It also checks twenty-six more addresses that the mod only reads. If an image is different anywhere, the page refuses it. It does not write the change in a place that only looks correct.

Where
On a synth track: [MOD], an LFO, turn DEST. They sit after the FX group, before the rest
Global
These are the machine's one Chorus, Delay and Reverb. Every track's LFO can aim at the same one, and they add up. That is what "global" means here. It is not a fault
Not included
Master. Its slots need destination codes above 127, and the firmware widens that byte as signed, so it needs a different edit
Writes
—

Confirmed on a Digitone II, 2026-09-23. We aimed an LFO on a synth track at Delay Feedback Gain. The feedback of the delay followed the LFO, and DEP and SPD did what they should. The owner's words: “works :) I can modulate with the LFOs the parameters.”

One extra fix rides along. Stock firmware has no short name for the Chorus group in its own group → name table. The slot holds the out-of-range fallback, which reads ERR. So the first build showed ERR over the Chorus entries while Reverb and Delay read REV and DEL.

This mod points that one slot at CHR, the short name that the Mix Vol. record of Chorus already carries. Reverb and Delay do not change.

3

Build it

The image is rebuilt, re-signed with the key derived from your own file, and every integrity field is checked again. Nothing downloads unless all of them pass.

Combining with other mods

Each page applies one mod. To combine mods, build here. Then load the downloaded file into the next page. Any order works, but A Fourth LFO goes last. This mod writes a few edits and one block of new code inside section 3, changes no length and appends nothing.

  • Modulation Destinations: combines. Different records, different bytes.
  • LFO Waves: combines. New waveforms to aim at these destinations with.
  • MIDI Arpeggiator: combines. No shared bytes.
  • Transient Swapper: combines. It only writes the DSP image.
  • Waverider: combines, in either order. Both answer the parameter lookup of the DEST list through the platform, each for its own parameters.
  • A Fourth LFO: combines, built here first. LFO4 copies the table this mod opens records in, so this page refuses an image LFO4 has already built.

What "combines" means here. A check makes sure that the bytes of the two mods do not overlap. That is the only guarantee. This mod passed on hardware alone. Nobody has flashed a combined image yet.
