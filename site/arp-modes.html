Digitone II Mods / arp modes

Arp Modes

The Digitone II names eight arpeggiator modes and offers five. This adds two of the missing ones, SHUF and RAND, as real modes with their own code. Select your firmware file. Then download a signed image.

Make sure that you can go back to stock before you flash a modified file. The Early Start-up Menu flashes the stock firmware over MIDI. Do this one time with the stock file, before you flash a modified file. Back up your +Drive. No tool here can recover it.

What it adds

The ARPEGGIATOR MODE menu goes on past CYCL to the two new modes, and stops at RAND. Before it writes, the page checks that each address this mod changes holds its stock bytes. If an image is different anywhere, the page refuses it. It does not write the change in a place that only looks correct.

SHUF
Plays every note in the range once per cycle, in a new order each cycle. The note that ends one cycle never starts the next
RAND
Picks a random note from the range on each step. The same note can come twice
The range
The notes you hold, across RNG + 1 octaves, as in the other modes
The rest
SPD, LEN, N.LEN, the step mask and the note offsets work as in every other mode: the new code only chooses the note
Not included
CHRD, the eighth name, stays hidden
Writes
—

A sound saved in SHUF or RAND opens with the arp OFF on stock firmware, or on any build without this mod. It is stored as mode 5 or 6, and stock turns anything above CYCL into OFF when it loads a sound.

Confirmed on a Digitone II, 2026-09-26. This page applies exactly the bytes of that build, checked byte for byte when it is packaged.

Build it

The image is rebuilt, re-signed with the key derived from your own file, and every integrity field is checked again. Nothing downloads unless all of them pass.

Combining with other mods

Each page applies one mod. To combine them, build on one page, then load the downloaded file into the next. This mod combines with every other one, in either order: it writes 8 places inside section 3, changes no length and appends nothing.

  • MIDI Arpeggiator: combines. The arp of a MIDI track runs the same step, so SHUF and RAND should reach MIDI tracks too. Nobody has tried that yet.
  • A Fourth LFO: combines, in either order.
  • LFO Waves, Boot Screen: combine. Their appended data moves no address this mod uses.
  • FX Modulation, Modulation Destinations: combine.
  • Transient Swapper: combines. It only writes the DSP image.
  • Arpeggiator p-locks: combines, from the command line only: dnfw mods apply firmware.syx --mod arpplocks --mod arpmodes. Its MODE lock then reaches SHUF and RAND too.

What "combines" means here. A check makes sure that the bytes of the two mods do not overlap. A test compares the output of this page with the output of the command line, byte for byte. The test runs this mod alone, and after the MIDI Arpeggiator or A Fourth LFO. The arp modes passed on hardware alone. Nobody has flashed a combined image yet.
