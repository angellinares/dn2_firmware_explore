Firmware Check

This page compares a modified Digitone II firmware file with Elektron's stock file. It shows a checklist of what changed and where. Use it before you flash a file, and for a file that you got from somebody else.

A checklist is not a guarantee. The page reads the two files. It does not run the new code. A file with no warnings can still have a fault. The list at the end tells you what the page does not check.

Supported: Digitone II OS 1.11 only. Your browser reads both files. Nothing is uploaded.

    What each line means

    The file is intact
    Every checksum and the signature of the modified file are correct. The instrument checks the same fields before it writes anything. If this line fails, the page stops.
    The stock file is a known Digitone II OS
    Each part of the stock file matches Elektron's OS 1.11 exactly. The page keeps only fingerprints of those parts, not the parts themselves.
    The same OS version and sections
    The modified file has the stock file's version, parts and load addresses.
    The bootstrap and the other recovery sections are stock
    Every part except the main OS and the DSP image is identical to stock. The bootstrap holds the Early Start-up Menu, which can always flash the stock OS again. If this line fails, do not flash the file.
    Changes inside stock's MAIN OS
    The places where the stock main OS changed, by address. A mod must change a few stock bytes to call its own code.
    The added code is a DNFW area
    Code added after the end of the stock main OS uses the format that this site's mods use, and the loader that copies it is in place.
    Run-time RAM stays out of stock's
    At start-up, the loader copies each added part to RAM. Every part must stay out of the RAM that the stock OS uses and out of the stack. No two parts can overlap.
    No new reference to stock's DMA buffers
    The stock OS keeps its buffers for the +Drive and USB in one area of RAM. New code that writes there damages saved projects. New code can also read there on purpose, so this line warns and does not fail.
    Changes in the DSP image
    The places where the sound processor's code changed. The page does not check the DSP's memory.
    The /modinfo record checks out
    A file with Waverider has a record that names its mods. Its fingerprint must match its bytes and the main OS.
    The record's mods rebuild this image exactly
    The page applies the record's mods to your stock file. Then it compares the result with the modified file. A pass shows that this site's patcher made the file, with no other change.
