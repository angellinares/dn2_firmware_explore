LFO ONE/HALF Fix

An LFO in TRIG MODE ONE should run one cycle and stop; in HALF, half a cycle and stop. The factory firmware gets both halves of that wrong. It stops at fixed points of the cycle rather than counting from the start phase, so with SPH moved the LFO ends early (or, in HALF, late). And when it stops it jumps to the centre: a square on the filter “turns off” or “jumps back to the middle”. This fixes both, on audio and MIDI tracks. Pick your firmware, download a signed image.

Everything happens in this tab. Your firmware file is never uploaded — this page has no server to upload it to. It is static files on GitHub Pages; you can read every line in the repository.

Prove your way back before you flash anything. The Early Start-up Menu reflashes stock firmware over MIDI. Do that once, with an unmodified image, before you flash a modified one — and back up your +Drive, which no tool here can recover.

What changes

Length
ONE runs one whole cycle from the start phase, HALF half a cycle, whatever SPH is and in either speed direction. Factory: ONE from SPH 96 plays a quarter of a cycle, HALF from SPH 64 a whole one
Hold
When it stops, the LFO stays at the value it reached instead of jumping to the centre. A square on the filter in ONE ends closed and stays closed; in HALF it stays open; a triangle in HALF stays at its peak
Where
Audio tracks’ LFOs and MIDI tracks’ LFOs, which the firmware runs through two separate copies of the same code
Unchanged
FREE, TRIG and HOLD (TRIG still starts at SPH); the random waveform, whose SPH is SLEW; a retrig from the TRIG page, which restarts the LFO for a full run; the waveforms New LFO waveforms adds, where SPH means something else
Why
The firmware tests for “the middle” and “the end” of the cycle rather than “half a cycle / a cycle since the trig”, and stops by writing a fixed value per waveform into the output. The fix counts the cycle from the start phase (it starts the LFO at zero and adds the start phase back when the waveform is read) and removes those writes
Writes
—

Tested. The hold on audio tracks was confirmed on a Digitone II on 2026-10-08, against factory 1.11 on the same patch, as the first version of this fix (LFO hold, now superseded). The length and the MIDI tracks: in the emulator, factory against fixed over every mode, waveform, start phase, speed direction, fade and retrig pattern; only ONE and HALF change, and they now trace the free-running waveform until they stop. On the instrument, 2026-10-09, audio track: ONE and HALF run their full length from SPH 0 to 120 (74, 85, 100 and 120 among them) and hold the value they reached, with no click or flip at the end.

Reported by the community: the jump Source; the length with the start phase moved Source. OS 1.12 has the same code.
